## Coupling to Watch

- `AGENT_VERSION` currently drives Agent update availability in CE API responses.
  Cloud rollout should not fork this logic; it should set/pin the advertised
  version through Cloud deployment configuration or a compatible rollout service.
- Agent task delivery is HTTP heartbeat/poll based. Cloud must preserve this
  protocol unless a versioned Agent protocol change is introduced.
- Terminal uses WebSocket message schemas shared by backend, frontend, and Agent.
  Cloud reverse proxy/gateway changes must preserve upgrade headers and message
  compatibility.
- CE migrations are the source of truth for core schema. Cloud migrations should
  extend in a separate namespace and avoid modifying CE migrations in place.
- Frontend docs currently exist under both `docs/public` and `frontend/docs`.
  This duplication should be reconciled before broad Cloud docs work.
- Release workflows previously used `latest` tags. CE production compose now pins
  `DATRIXOPS_VERSION`; Cloud must pin exact versions in `community-version.yaml`.

## Secret Scan Findings

Commands checked file names and content patterns for `.env`, PEM/private keys,
GitHub tokens, database passwords, JWT secrets, API keys, Cloudflare tokens, SMTP
credentials, and Ed25519 signing keys.

Findings:

- No tracked `.env` file was found.
- No private key file (`*.pem`, `*.key`, `id_rsa`, `*.p12`, `*.pfx`) was found.
- `deploy/generate-secrets.sh` matched by filename only; it generates secrets and
  does not contain a static secret.
- Workflow references to `${{ secrets.AGENT_SIGNING_PRIVATE_KEY }}` and
  `${{ secrets.GITHUB_TOKEN }}` are expected and do not expose values.
- `.env.example`, Compose files, and CI use placeholders or runtime interpolation
  for `JWT_SECRET`, `POSTGRES_PASSWORD`, and `DATABASE_URL`.
- `backend/internal/scheduler/website_job_test.go` generates an RSA key in memory
  for TLS tests; this is test material, not a committed private credential.
- Git history regex matched commits that introduced placeholder config, signing
  tooling, generated/binary artifacts, and CI secret references. No literal
  high-confidence private credential was identified in the inspected matches.

If any historical binary artifacts are considered sensitive by policy, rotate
affected release artifacts and remove them in a separate history-cleaning plan.
Do not rewrite history without explicit approval.
